Module 1.1
The Switch to Multicore

By the end you can…

  • Explain the low-hanging-fruit theory of architectural progress
  • Contrast ILP and TLP, and say why we ran out of cheap ILP

Definitions

Parallel architecture An architecture where CPUs are integrated tightly enough that they can cooperate to solve a single problem.

What is a CPU (a "core")? A processing element that can independently fetch and execute instructions from at least one instruction stream.

  • Contains: instruction-fetch unit, program counter, scheduler, functional units, register file…
  • Does it include the L1 cache? the L2 cache? Yes and no — depends on context
Course convention A core is the logic that independently runs an instruction stream. We generally exclude caches from the definition.
The "yes and no" is deliberate: vendors draw the boundary differently. For this course, when we say "core" we mean the execution logic, and we'll talk about caches as a separate (shared or private) resource.

What is a Multicore?

MulticoreA single chip (die) containing multiple CPUs / cores.

Terminology used in this course:

  • Processor = CPU = core
  • Processor chip = the chip that holds the cores

Most multicores are parallel architectures; parallel architectures often use multicores as the building block.

Multicore ⊂ Parallel architecture (usually)

Recent Multicores

From a handful to many dozens of cores, most running multiple hardware threads per core (SMT).

  • Typically 3 levels of cache hierarchy
  • Large shared L3 / last-level cache — tens to hundreds of MB
  • On-die interconnect (mesh / ring) links cores + cache banks + memory controllers

The big question Starting ~2001–2005, every chipmaker turned to the multicore approach. Why then? Why not earlier or later?

Module 1.1 answers the "why now"; Module 1.2 gives the physics.

Feature Size Scaling

Moore's Law, visualized Transistor feature size fell from ~10 µm (1971) toward the nanometer scale today.
  • ~2,300 transistors (Intel 4004, 1971)
  • → billions of transistors per chip today (3 nm / 2 nm-class nodes)
  • Pace accelerated after 1990 (~30% every 1.5 yrs)

Abundant transistors are not the same as abundant performance — that's the twist in Module 1.2.

Why That Order? The Low-Hanging-Fruit Theory

More transistors became available steadily. So "single core → multicore" feels inevitable…

But why did pipelining, branch prediction, superscalar, and caches all come before multicore?

The theory A farmer picks the low-hanging fruit first — it takes the least effort — until they run out.
This metaphor is the spine of the whole chapter. Architects exploited the techniques that gave performance with the least programmer effort first (ILP, caches — invisible to the programmer). Multicore is "high-hanging" because it demands parallel programming.

Multicore Is Not Low-Hanging

TLP — Thread-Level Parallelism

  • Split program into multiple threads
  • Coordinate with synchronization
  • Communicate data across threads

Cost: real parallel-programming effort 😓

ILP — Instruction-Level Parallelism

  • Hardware finds parallelism automatically
  • Programmer keeps the sequential mental model

Cost: little to none for the programmer 🙂

So why switch? We switched from ILP to TLP only because we ran out of low-hanging ILP fruit. Multicore wasn't chosen for love — it was chosen out of necessity.

The ILP Fruits

Pipelining & issue

  • Pipelining (RISC; CISC with a RISC backend)
  • Superscalar (multiple issue / cycle)
  • Out-of-order execution

Memory hierarchy

  • Caches exploit spatial & temporal locality
  • Multiple cache levels (L1/L2/L3)

Next: three quick ILP techniques (pipelining, superscalar) and three flavors of parallelism we can expose instead.

ILP Technique: Superscalar

Original (sequential issue)

LD    F0, 34(R2)
ADDD  F4, F0, F2
LD    F7, 45(R3)
ADDD  F8, F7, F6
Scheduled (2-wide issue)

LD   F0,34(R2)  │  LD   F7,45(R3)
ADDD F4,F0,F2   │  ADDD F8,F7,F6
  • Moderate parallelism: theoretically ~50 inst/cycle, realistically ~2
  • Requires fast (register-level) communication between functional units

TLP Technique: Loop Parallelism

Parallel — iterations independent

for (i = 0; i < 8; i++)
    a[i] = b[i] + c[i];

✓ Each iteration is independent → split across threads.

NOT parallel — loop-carried dependence

for (i = 0; i < 8; i++)
    a[i] = b[i] + a[i-1];

✗ a[i] depends on a[i-1].

ProsVery high parallelism (> 1K); often easy load balance.
ConsNeeds splitting into instruction streams; some loops aren't parallel; some apps have few loops.

TLP Technique: Function Parallelism

Arbitrary independent code segments run concurrently.

Across loops / subroutines

Cost = getCost();    // independent
A    = computeSum(); // work
B    = A + Cost;     // joins them

e.g. an editor: GUI · printing · parsing as separate threads.

ProsLarger granularity → lower overhead & communication.
ConsLow degree of parallelism; hard to load-balance.

Program-Level Parallelism

Independent programs run together — e.g. a parallel make:


gcc -c code1.c     # → proc 1
gcc -c code2.c     # → proc 2
gcc -c main.c      # → proc 3
gcc main.o code1.o code2.o
ProNo communication between the compile jobs.
ConHard to balance; relatively few opportunities.

ILP: No Longer Low-Hanging

Deeper pipelines backfire [Hartstein & Puzak, 2002]

  • Latching overhead grows significant
  • Too little useful logic per stage
  • Critical loops (branch mispredict, data dependence, cache miss) scale with depth

Wider issue is quadratic [Palacharla & Smith, 1996]

  • Dependence checking, wakeup/select, register ports, bypass logic…
  • Complexity ↑ quadratically with width
Verdict More ILP now costs more power and complexity than it returns. The cheap fruit is gone — time to climb to TLP. But what physically forced the issue? → the Power Wall.

Module 1.2
The Power Wall

By the end you can…

  • Distinguish energy from power, and define EPI, EDP, ED²P
  • Decompose power into dynamic (CV²f) and static (leakage)
  • Explain why voltage stopped scaling and frequency stalled ~2005

Basics of Power & Energy

EnergyAbility to do work — unit joule.
1 J ≈ lift an apple to shoulder height · 4 J ≈ heat a teaspoon of water by 1 °C.
PowerRate of energy transfer — 1 watt = 1 J/s.   \(P = V \cdot I\)

For a capacitor: \(E_{stored} = \tfrac{1}{2} C V^2\)

Charged/drained f times per second:

\( P_{dynamic} = 2 \cdot \tfrac12 C V^2 \cdot f = C V^2 f \)

This dynamic power term drives everything in this module.

Efficiency Metrics

Energy efficiency

  • Energy per work — e.g. EPI (energy/instruction)
  • Power per throughput — e.g. Watt/IPS, Watt/FLOPS
\( \frac{W}{IPS}=\frac{J/s}{inst/s}=\frac{J}{inst}=EPI \)

Weighting performance in

  • EDP = Energy × Delay
  • ED²P = Energy × Delay² — emphasizes speed even more
Why?Two systems both use 1 J: A = 0.5 W for 2 s, B = 1 W for 1 s. Most prefer B — so we weight energy by delay.

The Power Wall Problem

Total power is capped by packaging (e.g. ~65–150 W desktop). It has two parts:

Dynamic powerCharging/discharging capacitive loads
\( P_{dyn} = A\,C\,V^2 f \)
A = fraction of gates switching · C = capacitance · V = supply voltage · f = frequency
Static powerLeakage even when idle
\( P_{stat} = V \cdot I_{leak} \)
\(I_{leak}\) grows fast as transistors shrink — the modern villain.

The Threshold-Voltage Dilemma

Lower V_thd (left) → faster… but leakage explodes.
Lower Vthd↑ max frequency almost linearly (good for performance).
…but lower Vthd↑ leakage current exponentially → static power blows up.
The dilemmaYou cannot keep lowering Vthd to chase speed — leakage punishes you. So V can no longer scale down freely.

Old vs. New Scaling Rule

Per generation, gate length scales by S = 0.7.

Old rule — Dennard scaling
  • C ↓ by S=0.7 · area ↓ by S²=0.5 → 2× transistors
  • V ↓ by S=0.7 · f ↑ by 1/S=1.4
\(P = ACV^2f \Rightarrow\) chip power constant 🎉
New rule — leakage-limited
  • C ↓ by 0.7 · still 2× transistors
  • V can't scale (would need lower V_thd → leakage)
  • f ↑ by 1.4
\(V\) fixed \(\Rightarrow\) chip power doubles every generation! 🔥
This is the wallDennard scaling ended (~2005). More transistors no longer come "for free" in power — so we can't just crank frequency anymore.

Implications for Architecture Design

FrequencyCranking the clock has hit a dead end.
ResourcesArea is abundant, power is scarce — the inversion.
Per-core budgetDeclining power budget per core.
New objective function Architectures must improve energy efficiency. The dominant metric becomes performance / watt (ops / joule) — and the answer is many simpler, cooler cores: multicore.

The Evidence: Frequency Went Flat (~2001–2005)

source: CPU DB (schematic)

Three empirical signatures of the wall, all hitting 2001–2005 — the same window as the multicore transition:

  • Clock frequency stops climbing
  • Logic per pipeline stage stops shrinking (pipelining reverses)
  • Power-saving techniques (clock gating, DVFS, power gating) become essential
Not a coincidenceThe power wall and the multicore pivot are the same event seen from two angles.

Worked Exercise

Q1If Moore's law slows so gate length scales at S = 0.8 (instead of 0.7), find dynamic power for the next generation under unlimited vs. limited voltage scaling.
Old / unlimited scaling C↓0.8 · area↓0.64 → 1.56× transistors · V↓0.8 · f↑1.25
\(P' = 1.56 \cdot 0.8 \cdot 0.8^2 \cdot 1.25 \approx 1.0\) → constant
New / leakage-limited V fixed, f↑1.25, 1.56× transistors
\(P' = 1.56 \cdot 0.8 \cdot 1.25 \approx 1.56\) → +56% / gen

Q2 — Keep dynamic power constant with V, f fixed by shrinking die area. By how much?

With S=0.7: 2× transistors at fixed V,f. To hold power constant, reduce area so the factor cancels → die area shrinks by ≈ 30% (1 − 1.4/2.0).

Parallel Computers

By the end you can…

  • Unpack the definition of a parallel computer (communicate + cooperate)
  • Explain why parallel machines were niche until multicore
  • Classify any system with Flynn's taxonomy: SISD / SIMD / MISD / MIMD

What Is a Parallel Architecture?

"A parallel computer is a collection of processing elements that can communicate and cooperate to solve a large problem fast."
— Almasi & Gottlieb

Three design axes hide in that sentence — we unpack each next.

☺ asideQ: Why did the parallel computers refuse to work together?   A: Too many "threads" of disagreement.

Unpacking the Definition

Collection of PEs What is a PE? How many? How powerful each?
Few powerful (Altix) vs. many small (BlueGene).
Communicate Shared memory vs. message passing. Interconnect: bus / crossbar / multistage. Sets cost, latency, throughput, scalability, fault tolerance.
Cooperate Synchronization sequences operations for correctness. Granularity & mechanism affect latency, load balance, fairness.
"…solve a large problem fast" General- vs. special-purpose: any machine solves some problems well. These axes — PEs, communication, cooperation — recur for the rest of the course.

Where Are Parallel Computers Used?

Embarrassingly parallelMany scientific codes — scale easily.
Medium parallelEngineering apps: finite-elements, VLSI-CAD.
Not parallelCompilers, editors — limited parallelism.
Modern realityAI/ML training & inference, data analytics, and graphics are now the dominant embarrassingly-parallel workloads driving GPUs and accelerators.

Why Parallel — and Why Not Until Multicore?

Why parallel?

  • Absolute performance: protein folding = years on one CPU, days on a parallel machine; weather forecasts must be timely
  • Cost-/power-adjusted performance, esp. small 2–8 chip systems — the smallest of which is a multicore

Why niche before ~2005?

  • Low-hanging ILP made single-thread perf scale cheaply
  • Parallel systems were costly & slow to design
  • ILP gains eclipsed parallel gains within a few years

Illustration: ILP Catches Up

100-processor system, perfect speedup, vs. one improving single processor:

  • Yr 1: 100× → Yr 2: 62.5× → Yr 3: 39× → … → Yr 10: 0.9×
Even worseMultiprocessors take longer to build · low volume → high prices · high prices delay adoption · perfect speedup is unattainable.

Flynn's Taxonomy [1972]

Classify machines by two independent dimensions:

Instruction streamInstructions fetched from a single program counter.
Data streamData items accessed by a single instruction.
Single DataMultiple Data
Single InstructionSISD — classic uniprocessorSIMD — vector, GPU
Multiple InstructionMISD — systolic (rare)MIMD — multicore, clusters

What's an "Instruction Stream"?

One PC points to one instruction; executed logically one at a time; PC advances.

C source

void MyFunction() {
  int a, b, c;
  a = 10; b = 5; c = 2;
}
→ one instruction stream (x86)

push ebp
mov  ebp, esp
sub  esp, 12
mov  [ebp-4], 10
mov  [ebp-8], 5
mov  [ebp-12], 2

SISD & SIMD

SISD

One PC; each instruction touches one data set. The classic uniprocessor / a single core today.

SIMD

One instruction, many data lanes. Exploits data parallelism. Examples: vector processors, multimedia extensions (SSE), GPUs.

SIMD in Code: SSE

SISD style — scalar loop

// C = A + B, element by element
for (i = 0; i < 4; i++)
    C[i] = A[i] + B[i];

Four separate add instructions.

SIMD style — 4×32-bit in a 128-bit reg

MOVUPS XMM0, [EAX]   ; load A[0..3]
MOVUPS XMM1, [EBX]   ; load B[0..3]
ADDPS  XMM0, XMM1    ; 4 adds at once
MOVUPS [Ret], XMM0   ; store C[0..3]

ADDPS = one instruction, four parallel adds.

MISD & Systolic Arrays

MISD = multiple instruction streams, single data stream. The rarest class.

  • Systolic arrays [Kung & Leiserson '79] — data "pulses" through a grid of PEs, each applying its own operation
  • Examples: space-shuttle computers (1984), Intel iWARP (1990)
ComebackThe systolic idea is alive in modern AI accelerators — Google's TPU matrix unit is a systolic array.

MIMD & Its Variants

MIMD = independent PEs, each with its own instruction and data stream. Most CPU parallel computers today

Variants differ by which level of the memory hierarchy is shared:

  • Shared main memory (SMP / multicore)
  • Shared cache (cores on one die)
  • Nothing shared (clusters / distributed memory)

The Taxonomy Today

SISDLives inside a single core — handles ILP.
SIMDThrives in GPUs & TPUs — data parallelism for HPC, blockchain, AI.
MIMDMulticore CPUs — TLP & complex parallelism.
MISDStill a niche — but systolic arrays power AI matrix engines.
Real systems combine all of them: a cloud/HPC server is SISD cores, SIMD GPUs, in a MIMD fabric.

top500.org ranks the fastest machines (by Linpack). It changes fast — Earth Simulator went #1 (2004) → #10 in two years.
